# どうぶつしょうぎ オンライン対戦

Firebase(Firestore + Anonymous Auth)を使ったリアルタイム対戦版どうぶつしょうぎです。
ビルド不要のプレーンHTML/CSS/JSで、GitHub Pagesにそのまま公開できます。

## ルール概要

- 盤面: 3列×4段
- 駒: ライオン🦁 / ゾウ🐘 / キリン🦒 / ヒヨコ🐤(相手最奥列で成りニワトリ🐔)
- 勝利条件: 相手のライオンを取る、または自分のライオンが相手陣最奥列に到達する(トライルールの簡易版・生存確認なし)
- 取った相手の駒は持ち駒になり、自分の手番に盤上の空きマスへ打てます

## セットアップ手順

### 1. Firebaseプロジェクトを作成

1. https://console.firebase.google.com/ で新規プロジェクトを作成
2. 「Authentication」→「Sign-in method」で **匿名(Anonymous)** を有効化
3. 「Firestore Database」を作成(本番モードでOK。ルールは後で設定)
4. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを追加し、表示された設定値を控える

### 2. 設定ファイルを編集

[js/firebase-config.js](js/firebase-config.js) の `firebaseConfig` を、controlしているFirebaseプロジェクトの値に置き換えてください。

### 3. Firestoreセキュリティルールを設定

Firebaseコンソールの Firestore →「ルール」タブに [firestore.rules](firestore.rules) の内容を貼り付けて公開してください。
(Firebase CLIを使う場合は `firebase deploy --only firestore:rules`)

ルールの要点:
- `games`: 更新できるのは対局の当事者のみ。空いている後手席に座れるのは、大会の対局なら指定された相手だけ。大会との紐づけ(`tournamentId`/`matchId`/`expectedGote`)は後から書き換え不可
- `tournaments`: 更新できるのは主催者と参加者(`playerUids`)のみ。受付中の大会への「自分だけを追加する」更新は誰でも可。`hostUid`/`format` は変更不可
- 手の合法性まではルールで検証していません(クライアント側で検証)。厳密な不正対策が必要ならCloud Functionsが必要です

### 3b. 古いドキュメントの自動削除(TTL、推奨)

部屋コード・大会コードは4桁(1万通り)で、ドキュメントは削除されないため、放置すると新規作成時の
コード衝突確率が上がります(衝突時はアプリ側で別コードを再試行しますが、空きが減るほど失敗しやすくなります)。
アプリは作成時に有効期限 `expiresAt`(対局=7日後、大会=30日後。再戦すると対局の期限は延長)を
書き込んでいます。Firebaseコンソールの Firestore →「TTL」タブで、次の2つのポリシーを作成してください。
ルール変更は不要です。

| コレクショングループ | タイムスタンプフィールド |
|---|---|
| `games` | `expiresAt` |
| `tournaments` | `expiresAt` |

TTLは「そのフィールドの日時を過ぎたら削除」という意味なので、`createdAt` を指定してはいけません
(作成直後に削除対象になります)。削除は期限から最大24時間ほど遅れて実行されます。

### 4. GitHubで公開(GitHub Pages)

```bash
git init
git add .
git commit -m "Initial commit: どうぶつしょうぎ"
git branch -M main
git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
git push -u origin main
```

その後、GitHubリポジトリの Settings → Pages で、Source を `main` ブランチ / `/ (root)` に設定すると、
`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

## 遊び方

1. 公開されたページを開くと匿名ログインが行われます
2. 名前(任意)を入力しておくと、相手や観戦者に「たろう(先手)」のように表示されます(次回も引き継がれます)
3. 「新しい部屋を作成」を押すと4桁の部屋コードが発行されます(自分が先手になります)
4. 「リンクをコピー」で招待リンクを相手に送るか、部屋コードを伝えます
5. 相手が部屋コードを入力して参加すると対局開始(後手になります)
6. 自分の駒 or 持ち駒をクリックして選択 → ハイライトされたマスをクリックで移動・打つ

対局画面の上部には「先手 たろう vs 後手 はなこ」の対戦カードが出ます。手番側は枠線で強調されるので、
観戦者(席が埋まった部屋に入った第三者)でもどちらが誰の手番か分かります。

## 大会モード(リーグ戦・トーナメント)

`tournament.html` から大会を作成できます(3人以上向け、人数は何人でもOK)。

1. 主催者が名前と形式(リーグ戦/トーナメント)を選んで「大会を作成」→ 4桁の大会コードが発行される
2. 参加者は名前と大会コードを入力して参加(リンク共有でもOK)
3. 主催者が「組み合わせを作って開始」→ 対局表が自動生成される
4. 対局表の「対局を始める」を押した人が先手になり、相手は「対局に参加」で入室
5. 対局が終わると結果が自動で大会に反映される

主催者は画面下の「この大会を削除する」から、大会と紐づく対局をまとめて削除できます
(確認のため大会コードの入力を求められます)。参加者リストは折りたたみ表示なので、
人数が多くても対局表が見やすいままです。

**一覧観戦**: 「進行中の対局をこの画面でまとめて見る」をONにすると、いま指されている対局の
盤面が小さく並び、リアルタイムに更新されます。誰と誰が対局中かと手番も分かります。

**リーグ戦(総当たり)**: 奇数人数は各回戦に休みが出ます。勝ち3点・引き分け1点で順位表を自動計算(タイブレークは勝ち数→直接対決)。

**トーナメント(勝ち抜き/シングルエリミネーション)**: 人数が2の累乗でない場合は自動的に不戦勝(バイ)が配置され、1回戦で解消されます。勝者は自動的に次の対局へ進出。決勝が引き分けた場合はその対局だけやり直しになります(トーナメントは必ず1人の優勝者が決まる必要があるため)。勝ち上がりは**トーナメント表(ブラケット図)**で表示され、勝者の枠が色付き、自分の試合は枠線で強調、右端に優勝者が出ます。

## CPU練習モード

`practice.html` からFirebase不要でいつでも練習できます。あなたが先手、CPUが後手で固定です。

CPUの強さは☆1〜☆10の7段階で、かんたん→ふつう→つよい→弱定石→中定石→強定石→最強の順に
ステップアップします。強さの表示(★の数)と実際のCPUロジックは `js/cpu-ai.js` の
`TIERS` という同じデータから生成されるので、表示と実装が食い違うことはありません。

| 難易度 | ★ | 内容 |
|---|---|---|
| かんたん | ★1 | 完全ランダム |
| ふつう | ★3 | 2手先まで読むミニマックス探索 |
| つよい | ★5 | 4手先まで読む |
| 弱定石 | ★6 | 序盤2手だけ定跡(下記)を使用、以降4手読み |
| 中定石 | ★7 | 序盤4手を定跡通りに、以降6手読み |
| 強定石 | ★8 | 定跡5手をフル活用、6手読み+最善手からのブレも少なめ |
| 最強 | ★10 | 定跡5手+8手読み、常に単独の最善手を選択 |

盤がとても小さい(3×4)ため、8手読みでも最悪数秒程度で計算できます(10手読みは局面によって
数十秒かかることがあるため採用していません)。

**定跡(オープニングブック)**: 「ゾウ冠」基本形の最初の5手を実装しており、実際のルールエンジンで
全手が合法であることを検証済みです。対局画面の「学習モード」をONにすると、選んだ難易度に
関係なくCPUが定跡通りに指し、あなたの番では次の一手のヒント(盤面のハイライト+解説)が
表示されます。定跡と難易度表示・CPUの強さの元データは
[`docs/strategy-guide.md`](docs/strategy-guide.md) にまとめています。

## ローカルでの動作確認

Firebase SDKをCDNから読み込んでいるため、`index.html` をローカルサーバー経由で開いてください(file://だとCORS等で失敗する場合があります)。

```bash
npx serve .
# もしくは
python -m http.server 8000
```

## ファイル構成

- `index.html` — ロビー/対局画面
- `css/style.css` — スタイル
- `js/game-logic.js` — どうぶつしょうぎのルールエンジン(Firebase非依存の純粋関数群)
- `js/firebase-config.js` — Firebaseプロジェクトの設定(要編集)
- `js/app.js` — Firebase連携・UI制御(大会の対局結果を自動反映する処理を含む)
- `tournament.html` / `js/tournament.js` — 大会モードの画面と制御
- `js/tournament-logic.js` — 総当たり/トーナメント組み合わせ生成・不戦勝処理・順位計算・結果反映(Firebase非依存)
- `practice.html` / `js/practice.js` — CPU練習モードの画面と制御(Firebase不要のローカル対局)
- `js/cpu-ai.js` — CPUの思考ルーチン(ミニマックス+アルファベータ枝刈り、Firebase非依存)
- [`docs/strategy-guide.md`](docs/strategy-guide.md) — 定跡・戦略まとめ(難易度別)。将来の攻略サイト記事化とCPU強さ調整の元データ
- `firestore.rules` — Firestoreセキュリティルール
